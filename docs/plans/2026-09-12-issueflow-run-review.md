**What is already addressed**

0.15/0.16 already contain bounded plan-review recovery, automatic time windows within a cumulative cap, controller-observed test receipts, immutable attempts, cancelled-wave recovery, remote-operation journaling and cached review context. Those are existing capabilities, not new proposals. In particular, #266's old terminated-worker/missing-delivery deadlock is historical; the fresh startup failure above remains reproducible in 0.16.0. The reviewed release documents describe live Codex recovery checks, but this audit did not rerun those campaigns or establish Claude/Codex parity.

**Implementation order and measurement**

| Order | Change | Primary benefit |
|---|---|---|
| 1 | Atomic initialization and same-owner retry | Remove recurring startup failures and unnecessary decisions |
| 2 | One fetched base plus policy/contract preflight | Prevent expensive restarts and deterministic review blockers |
| 3 | CI classification and receipt-derived status | Make readiness usable and claims accurate |
| 4 | Explicit final handoff and authorized continuation | Carry work to the intended stopping point |
| 5 | Published amendments and convergent plan repair | Recover larger issues without abandoning the controller |

Compare the installed baseline and candidate on the same cases. Track time to first implementation, time to reviewed PR, time to authorized completion, worker time, controller/test time, CI wait, human wait, restarts, repeated plan reviews and decisions caused by harness defects. Report failed/abandoned runs too. Do not infer speedup or cost from these heterogeneous transcripts. Controller verification already supports receipt reuse; preserve its code/input/contract checks rather than rerunning identical full suites indiscriminately or weakening verification.
