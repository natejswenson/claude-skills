# Gmail triage local decision integration

## Intent and scope
User asked to implement the revised local Jev-like decision plan after the standalone prototype was verified. Extend Gmail triage with an opt-in `suggest-local` command and its agent instructions. Codex remains the orchestrator. The external local classifier already exists and is independently versioned/configured; bundle no weights or Python dependencies. No Gmail access during development, no automatic rule changes or mailbox actions, no release/merge.

## Interfaces
`node <SKILL_DIR>/scripts/gmailtriage.js suggest-local --threads <ingested.json> --labels <labels.json> --choices <choices.json> --scratch-dir <session-dir> [--rules <rules.json>] [--config <local-model.json>] [--min-count N] [--out <suggestions.json>]`
Default config is ~/.gmailtriage/local-model.json. Schema: {version:1,python:"/absolute/env/bin/python",script:"/absolute/decide.py",modelDir:"/absolute/local-cache"}. Exact fields, absolute existing paths, python/script files and modelDir directory; no shell commands or remote URLs. Config is local personal state, no committed machine paths. No threshold configuration: .8/.2 provisional policy fixed for initial integration.
Choices file is an array of 2..12 exact {label,description} records: unique existing user-label names, nonempty descriptions <=200 Unicode characters. Existing snapshot labels are authoritative; reject missing/ambiguous/system destinations before any runner executes. Use opaque internal choice IDs instead of Gmail IDs; map accepted results back to actual label names. No generated folder names.

## Eligibility and payload
Use propose(threads,{minCount,labels,rules}) as the authority. Only its sortable rows with keepInInbox!==true and destination===null are eligible. This preserves whole-sender claimed-rule precedence, conservative sender parsing, self-sent exclusion, whole-cluster protected subjects and threshold. Already matched destinations are not overridden. Validate rule files through validateRuleSet first, including defaults; absence is empty. No lower-confidence duplicate eligibility heuristics. Protected sender kinds such as recruiting/education are eligible when the existing proposal permits sorting and their subjects are not sensitive.
Send one candidate sample subject, resolved sender and opaque item ID per eligible row. Only these metadata fields and explicit choices enter the request. No thread IDs, snippets, bodies, arbitrary fields or metadata for excluded senders. Enforce the classifier bounds (sender254,subject160,id64,20items,12choices) with Unicode code point length; refuse overflow rather than truncate or silently omit. If no eligible rows, return kind=local-label-suggestions, empty suggestions and counts without starting a process. If >20 candidates, fail explicitly and ask for a smaller sample. Min-count must be a positive integer.

## Process and result boundary
Use Node stdlib child_process execFile, shell=false, args array: script --input private-request --model-dir config.modelDir --min-score 0.8 --min-margin 0.2. Force HF_HUB_OFFLINE=1, HF_HUB_DISABLE_IMPLICIT_TOKEN=1, TRANSFORMERS_OFFLINE=1. Limit process to90seconds, maxBuffer1MiB, metadata-free fixed errors. Never forward runner stdout/stderr or exception data on failures. Use an explicit session scratch directory outside Git, including symlink-resolved containment checks, and private unique subdir/request mode0700/0600. Clean only this command's unique temporary subdir in finally, on success/failure/timeout. No writes into repositories even --allow-repo; optional output uses existing writeJson refusal plus canonical-path preflight. Do not execute runner if scratch/output invalid. Rules, snapshots, labels and config remain byte-for-byte unchanged.
Require schemaVersion1, scoreKind=uncalibrated_entailment, calibration=none, thresholds exactly.8/.2, model nonempty id/revision, exact item/choice ID membership and one result per item. All scores finite0..1, booleans invalid. Derive top/margin and suggest/abstain from scores at the Node boundary; reject a returned decision,choiceId,reason,topScore,margin inconsistent with policy (numeric comparisons tolerance1e-6 only for arithmetic; never use tolerance to lower acceptance thresholds). Reject unexpected properties to prevent model-invented action fields. Independent scores need not sum to1. Never trust asserted confidence alone.
Return {schemaVersion:1,kind:"local-label-suggestions",scoreKind:"uncalibrated_entailment",calibration:"none",model,thresholds,counts,suggestions:[{candidateId,from,decision,destination,topScore,margin,reason}]}. `candidateId` is a new opaque per-request ID; `from` is a deterministic input sender for human review, never model output. No subjects/snippets/rule matchers/action fields. Score thresholds are heuristics, not calibrated probabilities. Output is not an importable rule document. No model-derived rules accepted without user review and existing validation. Print named columns Candidate/Sender/Suggestion/Top score/Margin/Result; emit output file only after full response validation. With no --out, human table only; report counts and advisory nature.
